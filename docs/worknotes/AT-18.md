# AT-18 — Decompose ExtractionOrchestrator.cs

Branch: `refactor/at-18-decompose-orchestrator`. Behavior-preserving; maintainability only.

## Approach: partial-class split (matches the repo's Storage precedent)

`ExtractionOrchestrator.cs` (1,264 lines) is one class = coordinator + ~20 helpers in
physically-contiguous clusters. Split into `partial class` files (same class, same members,
no API/behavior change — exactly how `SqliteAtlasRepository.*.cs` is already split):

- `ExtractionOrchestrator.cs` — coordinator: fields, ctors, `RunAsync`, `RunPreparedAsync`, `RunResolvedCoreAsync`.
- `ExtractionOrchestrator.Types.cs` — top-level types: `ExtractionOptions`, `ExtractionOperationResult`, `IExtractionOrchestrationLockLease`, `ExtractionOrchestratorDependencies`, `ExtractionOrchestrationLockLease`.
- `.Lifecycle.cs` — CreateDependencies, CreateAttempt, CreateExecutionFacts, TransitionAsync, WriteActiveDocumentAsync.
- `.Execution.cs` — CreateOwnedExecutionDirectories, ApplyProcessResult, ApplyCanceledProcessResult, MoveProcessLogs, PromoteCandidateOutput.
- `.Failure.cs` — FinalizeTerminalFailureAsync, FinalizeFailureLogs, FinalizeOneFailureLog, MoveExactLog.
- `.Filesystem.cs` — InspectOwnedOutput, EnsureSafeStaging, DeleteOnlyEmptyOwnedStaging, DeleteDirectoryIfEmpty.
- `.FailureMapping.cs` — MapFailure, MapToolFailure, PersistenceFailure, FilesystemFailure + nested `OutputFacts`/`TerminalFailureResult` records.

Executed by exact line-slicing from a backup (no hand-copy). Largest resulting file is the
coordinator (~460 lines, dominated by the 380-line `RunResolvedCoreAsync`) — well within the
repo's accepted range (Storage partials run 500–1,554 lines). Breaking `RunResolvedCoreAsync`
itself into phase sub-methods is a riskier follow-up (shared mutable locals threaded through);
out of scope here.

## Verify

- Split with full usings on every file, then `dotnet format` (prunes unused usings) → build → test.
- Full `dotnet test` green (esp. Extraction.Tests 551 + IntegrationTests + FakeCpp2Il).
- `dotnet format --verify-no-changes` + hygiene gate + code-map regen (misc.md was stale v0.2.0).

## Gotchas

- Private nested types (`OutputFacts`, `TerminalFailureResult`) live in `.FailureMapping.cs` but
  are used from other partials — fine, one class across files.
- `ExtractionOrchestrationLockLease` + the records/interface are top-level (not partial members) → Types file.
